# Legacy Hash Fixtures

## Overview

This directory contains synthetic password hash fixtures for all legacy hash formats supported by `PasswordService.verify()`.

## Current State: Synthetic Fixtures

**These hashes are synthetic (generated programmatically), not from production.**

All fixtures represent the password `TESTE_SENHA_2025` (the test account password documented in the project's password reset procedures).

### Fixture Format

Each fixture is an object with:
- `format`: Hash algorithm identifier (`"gotrue"`, `"wp"`, `"phpass"`, `"md5"`)
- `hash`: The actual hash value
- `password`: The plain text password these fixtures represent
- `synthetic`: Boolean flag; `true` for synthetic, `false` for real production hashes

## Replacing with Real Hashes

The fixture test is designed to catch regressions in `PasswordService` when a real production hash export becomes available. To swap in real hashes:

1. **Export from production database:**
   - Query `wp_users_legacy.user_pass` for one row each with format `"wp"`, `"phpass"`, and `"md5"`
   - Query `auth.users.encrypted_password` for one Supabase GoTrue hash (format `"gotrue"`)
   - Select accounts whose passwords are known or can be reset to `TESTE_SENHA_2025`

2. **Update fixtures:**
   - Replace the `"hash"` field for each format with the real hash from production
   - Set `"synthetic": false` for each entry
   - Leave `"format"` and `"password"` unchanged
   - Do not modify the test spec; it will continue to work as-is

3. **Verification:**
   - Run `npm test -- fixtures` to confirm all formats still pass
   - This confirms the real hashes are compatible with the current implementation

## Verification Status

### Real-Hash Validation (2026-09-04)

The positive-case verification for **bcrypt (Supabase GoTrue)** and **WordPress `$wp$2y$`** has been completed against real production and real-WordPress hashes:

- **bcrypt (`$2a$10$`):** Validated against a real production account. Correct password verified `{valid: true, needsRehash: false}`, wrong password rejected, leading/trailing spaces handled correctly (trimmed). **CLOSED.**
- **WordPress `$wp$2y$` (WP 6.8, HMAC-SHA384+bcrypt):** Validated against three real WordPress-generated hashes. Correct password verified `{valid: true, needsRehash: true}`, wrong passwords rejected. **CLOSED.**

**Still open:** phpass needs a real hash with a known password:
1. **phpass (`$P$`/`$H$`) positive case:** Cannot be verified because the cleartext password for the only available production hash is unknown. The fixture is generated by the same library that verifies it, so a shared bug could pass undetected. Awaiting a real hash whose password is known.

**Updated 2026-10-18:** `$wp` verification now tries the official WordPress
HMAC-SHA384/base64 input first and retains the previous transformed input as a
compatibility fallback. Independent algorithm tests cover ampersand, both kinds
of quotes, angle brackets, backslash and Unicode. WordPress does not apply
`htmlspecialchars` at this hashing step; the earlier apostrophe explanation
above was incorrect. A real-account smoke test remains required before cutover.

### Synthetic Fixtures

These synthetic fixtures remain the automated regression test and will continue to exercise all four formats. When a real-hash pair becomes available (known cleartext + corresponding hash), the procedure in "Replacing with Real Hashes" above may be used to add a permanent verification step to the test suite.
